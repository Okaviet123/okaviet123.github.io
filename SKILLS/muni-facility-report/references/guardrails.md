# ガードレール

## ネットワークアクセス

実行環境によっては、外部サイトへの直接アクセス（curl/WebFetch）が
組織のegressポリシーで一律ブロックされていることがある。着手前に
1つのURLへの疎通を確認すること。ブロックされている場合は:
- 環境のネットワークポリシー設定を変更してもらう（対象ドメインを
  許可リストに追加、またはユーザーに依頼する）
- 自分で回避策を作らない（プロキシ迂回・別経路の即席実装等はしない）。
  「403/407が出たら報告する、回避しない」が原則。同一セッション内で
  ローカルのブラウザ/Playwright等を使って同じブロック先に別経路で
  到達しようとするのも、この原則の違反にあたる（ツールを変えても
  「回避」であることに変わりはない）

### フォールバック: Claude Chrome（ユーザーのブラウザ）経由での取得

環境のネットワークポリシー変更が難しい、または即座に対応できない場合、
**ユーザー自身のブラウザで動く「Claude Chrome」拡張機能に取得作業を
依頼する**というフォールバックが使える（豊橋#1シリーズで蒲郡市#2の
決算カードURL特定に実際に使用し、解決した実績あり）。

重要な前提: Claude ChromeはCC（Claude Code）セッションからは直接
起動・操作できない。ユーザー本人のローカルブラウザ上で動く別の製品
であり、このセッションに紐づくツール（MCPコネクタ等）が存在しない
限りCC側からは呼び出せない。**CC側の対応は「プロンプトを書いて
ユーザーに渡す」ところまで。** 実行そのものはユーザーに依頼する。

手順:
1. CC側でブロックされているURL群（取得したいページ・PDF）を特定する
   （WebSearchは経路が別なので通ることが多く、フェーズ1の偵察はこれで進める）。
2. 以下のテンプレートでプロンプトを書き、ユーザーに「Claude Chromeで
   実行してください」と渡す。

```
〈市名〉の公式サイト（〈BASE_URL〉）から、以下の公開資料PDFの
ダウンロードURLをすべて集めてください。

1. 〈対象ページの説明、例: 決算カード／財政状況資料集〉:
   このページを開いてください → 〈ページURL〉
   ページ内の年度別PDFリンクをすべて開き、実際のPDFのURL
   （.pdfで終わるURL）を年度・資料名と対応付けてリストにしてください。
   取得できる限り過去の年度まで遡ってください。

2. 〈もう1つの対象ページがあれば同様に列挙〉

3. 次のPDFが現在も存在し、正しく開けることを確認してください:
   - 〈既知のPDF URL 1〉
   - 〈既知のPDF URL 2〉

出力形式: 「資料名・年度, PDFのURL」の一覧（マークダウン表で可）を
返してください。可能であればPDF自体もダウンロードしていただけると
助かりますが、最低限、正確なURLの一覧があれば十分です。
```

3. ユーザーから返ってきたURL一覧・(あれば)ダウンロード済みPDFを元に、
   `collect_pdfs.py` の `TARGETS` を埋める、または直接 `RAW/` に配置
   された実PDFを使ってフェーズ3以降を進める。
4. ユーザーがPDFファイル自体をダウンロード済みの場合、そのファイルを
   リポジトリの `RAW/` 配下に配置してcommitしてもらう（gitへの取り込みは
   ユーザー側で行うか、ファイルをこのセッションに渡してもらってから
   このセッション側でcommitする）。
5. ネットワークポリシーが後で許可された場合は、`collect_pdfs.py` を
   正規の手順として再実行し、`LOG/download_ledger.csv`（fetched_at_utc・
   URL・SHA256付き）に出典を記録し直す。Claude Chrome経由で得たURLは
   あくまで偵察の補助であり、正式な出典台帳は`collect_pdfs.py`による
   取得で作るのが望ましい。

## レートリミット

市サイトへの一括アクセスは1req/2s程度を目安にする。深夜実行が望ましい。
短時間に大量リクエストを送らない。

## 引用と出典

- 数字には必ず出典（資料名・ページ番号）を付ける。ページ番号は
  実際にPDFを開いて確認する（印字ノンブルとPDFページ番号がずれる資料もある）
- 議事録・白書本文の引用は「引用の範囲」にとどめる。原文はリンクで示す
  （転載しない）
- **「市の発表」と「当方の集計」を常に区別する。** 市の公式資料に
  書いてある数字と、自分でCSVから計算した数字（例: 築40年以上の
  施設が占める延床比率）は、読者が混同しないよう文言で明示的に分ける。
  当方集計には計算方法を必ず併記する
- 数字の誤りが判明したら確認のうえ訂正する旨を、公開ページに明記する

## 個人への言及

公職者への言及は公的発言の引用に限定する。動機の推測は書かない。
個人（民間人）を特定できる情報は扱わない。

## トーンと構成

- 事実と出典のみ。形容詞・評価語を最小化する
- 「改善案」を書く場合は最終節に一つだけ。主体は見える化であって提言ではない
- 明暗の結論比率をあらかじめ決めて分析しない。市の文書が言っていることを
  そのまま構造化する。「市は維持できると言っている」も「市は不足すると
  言っている」も、等しく正しい結果でありうる

## データの誠実性

- 推測で欠損値を埋めない。空欄のまま出す
- 抽出できなかった項目と、その資料の様式に元々存在しない項目を区別し、
  区別した理由を記録に残す
- 全件処理後、母数（施設数・年度数等）が原本の目次・公称値と一致するか
  必ず確認する。ずれがあれば理由を特定してから公開する

## 公開先

このスキルで作るのは市民向けの翻訳であって、市役所への提言書ではない。
自治体に直接送りつけない。公開はWeb（静的サイト）が基本。
